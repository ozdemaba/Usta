# Phase 2 database contract

## Scope

Phase 2 establishes the durable application data foundation required before ingestion, search, map aggregation, and AI agents.

### Tables

- goi_organisations: buyers, government bodies, suppliers, agencies, and other organisations.
- goi_countries: canonical ISO country records and map anchors.
- goi_regions: hierarchical administrative/geographic areas.
- goi_data_sources: source registry and source health metadata.
- goi_opportunities: canonical opportunity records after normalisation.
- goi_opportunity_sources: provenance links between canonical opportunities and source observations.

## Rules

1. Source records are never treated as canonical truth without normalisation and provenance.
2. External identifiers remain source-scoped; canonical UUIDs are generated by GOI.
3. Timestamps are stored in UTC.
4. Country identifiers use ISO codes.
5. Deadline and status indexes support the Ending Soon engine.
6. Schema changes are forward migrations and must be executed through the signed control-plane release path.
7. dbDelta() is used for WordPress-compatible schema creation; application-level relationships are used instead of hard foreign keys.
8. Larger procurement, trade, vector, and analytics datasets can move to PostgreSQL/PostGIS without changing the public GOI domain model.

## Phase gate evidence

The phase is not complete until:

- PHP 8.1/8.2/8.3 lint passes.
- Security execution-API scan passes.
- Schema contract test passes.
- Signed release packaging can produce a manifest for the Core version.
- A fresh install and an upgrade from schema 1.0.0 are tested on WordPress.
- Control-plane migration reaches schema 1.1.0 and health checks remain green.
